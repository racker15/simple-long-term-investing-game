# Git publication and authoring chronology

The methodology’s short commit IDs refer to the original local authoring history. The protocol was committed before the real draw, the draw before new outcome research, and each starting lock before its outcomes. Shell Git had no HTTPS credentials or SSH identities in this session, so the authorized PR branch was published through the authenticated GitHub connector.

The connector creates its own author/time metadata and therefore produces different commit IDs. Each original commit was published in the same order, with the preceding published commit as parent. Every resulting Git tree SHA was checked against the original tree SHA: all file contents and modes match exactly. Every published commit message also includes its full original local Git commit object, including parent, author, committer, timestamps and message. This distinguishes publication timestamps from research chronology and allows reconstruction of the original commit IDs. The untouched merged base and the existing September 1999 pilot keep their original IDs.

The final verification/production-audit revision is a subsequent commit and uses the same publication method. It changes no locked starting bytes and performs no real expanded production draw. The original authoring branch is retained locally as `codex/six-scenario-authoring-history`; the PR branch is `codex/six-scenario-qualification`.

To verify an original authoring object, extract everything after `Original-Git-Commit-Object:` from the corresponding published commit message, preserving its final newline, and run `git hash-object -t commit --stdin`. The result must equal the original ID above. Its `tree` line must equal both the published commit’s tree and the table. Following the original parent IDs establishes the authoring chain; following the published parent IDs establishes the identical-tree publication chain. These are ordinary unsigned Git records, not an external timestamp attestation.
